Make apps for MaterialTV

The Get apps row installs two kinds of full-screen app: Android TV apps from a GitHub release, and MaterialTV web apps written in HTML. Here's how to make either and get it in front of everyone.

Build a web app Publish an Android app Open the sample

Two ways in

Anyone can add either kind from the phone page (Your apps), and either can be listed for everyone in the catalog, store.json, with a pull request.

Android TV app

  • An APK in a GitHub release, or at an https link
  • Kotlin, Java, Flutter: anything that makes an APK
  • Runs as its own Android app and can do anything one can
  • MaterialTV downloads and checks it; Android asks you to confirm

MaterialTV web app

  • A manifest.json and a web page on any https host
  • HTML, CSS and JavaScript
  • Full screen inside MaterialTV, with the window.materialtv bridge
  • Installs instantly; nothing for Android to install

Android TV apps

Already have an Android app? A few manifest lines and a release make it installable from Get apps.

  1. Make it work on a Fire TV

    • minSdk 28 or lower. Fire OS 7 is Android 9 (API 28); Fire OS 8 is Android 11.
    • 32-bit ARM. Fire TV sticks run 32-bit Android, even on 64-bit chips. Ship an armeabi-v7a or universal APK; an arm64-only APK won't install.
    • No Google Play services. Fire TV doesn't have them.
    • The remote does everything: every control is reachable with the D-pad, focus is obvious, Back goes back.

  2. Add a TV launcher entry and a banner

    So MaterialTV and Fire OS list it as a TV app. The banner is 320 × 180 px (xhdpi); tiles use your sharpest launcher icon.

    <uses-feature android:name="android.software.leanback" android:required="false" />
<uses-feature android:name="android.hardware.touchscreen" android:required="false" />

<application android:banner="@drawable/banner" android:icon="@mipmap/ic_launcher" ...>
    <activity android:name=".MainActivity" android:exported="true">
        <intent-filter>
            <action android:name="android.intent.action.MAIN" />
            <category android:name="android.intent.category.LEANBACK_LAUNCHER" />
        </intent-filter>
    </activity>
</application>

  3. Publish a GitHub release

    The release's tag is the version (v1.4.0 or 1.4.0). Attach the APK as an asset. MaterialTV picks it like this:

    • names with arm64, aarch64, x86 or x64 are skipped;
    • names with armeabi, armv7, arm32 or a separate word arm come first, then universal, then any other .apk; debug builds come last;
    • a catalog entry's asset_regex narrows the choice first.

    Keep versionName equal to the tag (without the v): Get apps shows Update when the tag's numbers are newer than the installed version. Sign every release with the same key, or Android refuses the update.

  4. Try it on your own TV

    On the phone page (Home > Get apps > Add an app > QR code), under Your apps, add a name and your repo as owner/name, or an https link straight to the APK. Before installing, MaterialTV checks the download is an app and that its package name is the expected one; Android then asks you to confirm.

MaterialTV web apps

A web app is a web page MaterialTV shows full screen, with no browser bars. The remote's arrows move focus for you, the page gets your theme's colours and font, and a small JavaScript bridge, window.materialtv, does the rest.

  1. Make three files

    Put them on any https host; GitHub Pages is free.

    my-app/
  manifest.json
  index.html
  icon.png        a square PNG, 256 × 256 or so

  2. Write the manifest

    {
  "api": 1,
  "type": "webapp",
  "id": "my-app",
  "name": "My App",
  "author": "You",
  "description": "What it does, in a sentence.",
  "version": "1.0.0",
  "icon": "icon.png",
  "start_url": "index.html",
  "orientation": "landscape",
  "permissions": ["storage"]
}

  3. Write the page

    Plain HTML. The theme stylesheet gives you MaterialTV's colours from the first paint; the fallbacks keep it working in any browser.

    <!doctype html>
<html lang="en">
<head>
<meta charset="utf-8">
<meta name="viewport" content="width=device-width, initial-scale=1">
<link rel="stylesheet" href="https://materialtv.invalid/theme.css">
<style>
  body { margin: 0; padding: 5vh 5vw; font-family: var(--mtv-font, sans-serif);
         background: var(--mtv-background, #141218); color: var(--mtv-on-surface, #E6E0E9); }
  button { font: inherit; font-size: 3vh; padding: 2vh 3vw; border: 0; border-radius: 3vh;
           background: var(--mtv-surface-high, #2B2930); color: inherit; }
  button:focus { background: var(--mtv-primary-container, #4F378B); outline: 3px solid var(--mtv-primary, #D0BCFF); }
</style>
</head>
<body>
  <h1>Hello, TV</h1>
  <button onclick="window.materialtv && materialtv.toast('Hi!')" autofocus>Say hi</button>
  <button>Another</button>
</body>
</html>

  4. Install it

    On the phone page under Your apps, add the manifest's link, like https://you.github.io/my-app/manifest.json. It appears in Get apps; select it and choose Install. It's now in All apps, and can be a favourite like any other app.

A complete example: Hello TV (manifest), with a clock, a focusable grid, the theme colours, a counter kept in localStorage and a sheet that Back closes. It's in Get apps under "Made for MaterialTV", and it runs in a desktop browser too.

The manifest must be served over https. MaterialTV reads it again whenever the app store refreshes (daily, or Settings > System), so a new name, icon or start page reaches everyone. The page itself is always live from your server.

Permissions

PermissionWithout itWith it
networkThe page loads only from the app's own origins (the manifest's, plus origins).It can fetch from any https address: APIs, CDNs, images.
storagelocalStorage, sessionStorage and Web SQL are off.They work and persist.

Camera, microphone, location, notifications and file pickers are always refused.

Where the app can go

  • Only https. http:// pages, mixed content, file:// and content:// are blocked.
  • The main page stays on the app's origins. A link elsewhere asks the viewer whether to open it in the browser; other schemes (intent:, market:, mailto:…) are blocked.
  • window.open() and target="_blank" open in the same view, under the same rule.
  • Frames may show any https page, but never get the theme or focus handling, and third-party cookies are off.

The remote

Remote buttons arrive as ordinary keyboard events, plus two MaterialTV events.

ButtonWhat the page gets
Up, down, left, rightkeydown with ArrowUp, ArrowDown, ArrowLeft, ArrowRight
Select (centre)keydown with Enter
Play/pause, rewind, fast-forwardMediaPlayPause, MediaRewind, MediaFastForward
Menua materialtv:menu event on window
Backa cancelable materialtv:back event on window; if nobody cancels it, history.back(); at the first page, the app closes
Hold Back, or HomeThe app closes. Always.

Spatial navigation

If your page doesn't handle an arrow key, MaterialTV moves focus to the nearest focusable element that way (links, buttons, inputs, [tabindex]), scrolls it into view, and scrolls the page when there's nothing further. Select clicks a focused element that isn't a link, button or input.

To handle keys yourself, call event.preventDefault() in a keydown listener on document or an element, or switch it off:

<meta name="materialtv:spatial-navigation" content="off">
<!-- or: window.materialtvSpatialNav = false; -->

Back for your own layers

Close a dialog or panel with Back instead of leaving the page:

window.addEventListener('materialtv:back', function (e) {
  if (dialogIsOpen) {
    e.preventDefault();
    closeDialog();
  }
});

The bridge

window.materialtv exists only inside MaterialTV, so check first: if (window.materialtv) { … }. It answers only while the page is on one of the app's origins. Values that aren't simple come back as JSON strings.

materialtv.keys()JSON: what each remote button sends.
materialtv.toast(text)A short MaterialTV message (120 characters, at most one a second).

var theme = window.materialtv ? JSON.parse(materialtv.theme()) : null;
if (theme && theme.isLight) document.body.classList.add('light');

Look native

Every page on the app's origins gets MaterialTV's colours as CSS variables. They follow the viewer's accent colour and light or dark mode.

CSS variables

--mtv-background, --mtv-surface-low, --mtv-surface, --mtv-surface-high, --mtv-surface-highest, --mtv-on-surface, --mtv-on-surface-variant, --mtv-outline, --mtv-outline-variant, --mtv-primary, --mtv-on-primary, --mtv-primary-container, --mtv-on-primary-container, --mtv-secondary-container, --mtv-on-secondary-container, --mtv-tertiary-container, --mtv-error, --mtv-is-light (0 or 1) and --mtv-font (Google Sans Flex).

<html> gets the classes mtv and mtv-dark or mtv-light. Focused elements get a primary ring unless you style :focus yourself.

From the first paint

MaterialTV adds the variables when the page starts drawing. To have them earlier, link the stylesheet it serves at a reserved address. It never resolves anywhere else, so in a normal browser your fallbacks are used.

<link rel="stylesheet" href="https://materialtv.invalid/theme.css">

Also there: font.ttf (Google Sans Flex, SIL OFL) and sdk.js (the focus and Back helper). When all is in place, window gets a materialtv:ready event whose detail is the theme.

Designing for the TV

  • The page is about 960 × 540 CSS pixels on a 1080p Fire TV (device pixel ratio 2). Size with vh/vw or rem.
  • Keep important things 5% away from the edges; some TVs crop them.
  • Make focus loud: a ring, a colour change and a slight scale. There's no mouse and no hover.
  • Text is read from the sofa: 2.5vh (about 14 CSS px) at the very least.
  • Avoid typing. If you must, the Fire TV keyboard opens for a focused <input> on Select.
  • The user agent ends in MaterialTV/<version> MaterialTV-WebApp/1.

Debugging

Build and test in desktop Chrome first: the sample works there with the arrow keys. On the TV, turn on ADB debugging (Settings > My Fire TV > Developer options), run adb connect <tv-ip> on a computer, and open chrome://inspect: running web apps appear there with full DevTools.

Privacy, storage and limits

  • Web apps run in their own process with their own web data, apart from MaterialTV and from Android apps. Leaving the app ends that process.
  • Storage is per origin, not per app. Android 9 can't give each web app its own storage, so two web apps on the same origin (you.github.io/app-one and you.github.io/app-two) share localStorage, cookies and IndexedDB. Give each app its own origin (a custom domain or subdomain), or prefix your keys with your app's id.
  • Uninstalling removes the tile, icon and pins. The web storage stays on the device (it's there again if you reinstall); clearing MaterialTV's data removes it.
  • Pages inside frames can reach window.materialtv too. Don't frame pages you don't trust.
  • Safe Browsing is on, certificate errors are never bypassed, and third-party cookies are off.

Get listed

Everyone's Get apps row comes from store.json on this site; the APK carries a copy, assets/store.json, for the first run and offline. Open a pull request on GitHub that adds one entry to both files.

{ "id": "jellyfin", "name": "Jellyfin", "package": "org.jellyfin.androidtv", "category": "Video",
  "description": "The Jellyfin media server's Android TV app",
  "icon_url": "https://example.com/jellyfin-512.png",
  "source": { "type": "github", "repo": "jellyfin/jellyfin-androidtv",
              "asset_regex": "^jellyfin-androidtv-.*-release\\.apk$" } }

What gets accepted: the download comes from the maker (their releases or site); it works with the remote; it's free of malware, injected ads and tracking beyond what the official app does; and it says honestly what it is.
